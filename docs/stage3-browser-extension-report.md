# 阶段3浏览器扩展打通报告

> 日期：2026-08-10  
> 范围：阶段3第一小步，Chrome MV3 扩展把用户主动采集的当前页面保存到本地 API。  
> 边界：不读取密码、Cookie、Token 或登录态；不做后台批量采集；不自动翻页；不绕过验证码或平台限制。

## 已完成

- 新增本地 API：`POST /api/browser/collect-page`。
- 扩展弹窗点击后读取当前页面公开信息：标题、URL、作者 meta、描述 meta。
- 扩展将页面信息发送到 `127.0.0.1:17860` 本地 API。
- 本地 API 自动创建或复用“浏览器采集素材”项目。
- 采集页面会写入 `search_results`，来源标记为 `browser-extension`。
- 页面会同步收藏到项目素材库，并自动添加“浏览器采集”标签。
- 服务层测试覆盖浏览器页面采集入库和非法 URL 拦截。

## 未完成

- 尚未针对 B站、小红书、抖音、视频号做页面结构专用解析。
- 尚未从页面读取封面、视频时长、发布时间、播放量等平台字段。
- 尚未在桌面端做“来自浏览器扩展”的单独入口或实时通知。
- 尚未做扩展手动加载、真实网页点击采集的人工验收记录。

## 下一步建议

- 给浏览器采集入口补平台字段解析，先从通用 `og:*`、`twitter:*` meta 开始。
- 桌面端素材库增加来源提示和刷新提示，方便用户采集后马上看到素材。
- 做一次 Chrome 扩展手动加载验收：打开公开网页，点击扩展，确认本地素材库出现该页面。
